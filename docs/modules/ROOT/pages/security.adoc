= Security

Snello does not ship its own security layer: the generated resources are
regular JAX-RS endpoints, so the standard
link:https://quarkus.io/guides/security-authorize-web-endpoints-reference[Quarkus HTTP security policies]
apply to them.

For example, with basic authentication and
`quarkus-elytron-security-properties-file`:

[source,properties]
----
quarkus.http.auth.basic=true

quarkus.http.auth.permission.developers.paths=/api/developers/*
quarkus.http.auth.permission.developers.policy=authenticated
quarkus.http.auth.permission.developers-list.paths=/api/developers
quarkus.http.auth.permission.developers-list.policy=authenticated
----

Both the snello collection `GET` and the CRUD endpoints generated by REST Data
with Panache are covered: unauthenticated requests receive `401`.

Role-based policies work the same way:

[source,properties]
----
quarkus.http.auth.policy.admin-only.roles-allowed=admin
quarkus.http.auth.permission.articles-write.paths=/api/articles/*
quarkus.http.auth.permission.articles-write.methods=POST,PUT,DELETE
quarkus.http.auth.permission.articles-write.policy=admin-only
----

Any Quarkus identity provider (OIDC, JWT, JDBC, LDAP...) can be combined with
these policies without touching the snello configuration.
